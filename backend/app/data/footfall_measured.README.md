# 유동인구 실측 전사 가이드 (`footfall_measured.json`)

유동인구 화면(`/diagnosis/[id]#visualize`)의 구역별 수치를 **사람이 옮겨 적은 실측치**로
바꾸기 위한 파일입니다. SK 유동인구 API는 별도 계약 상품이라 쓰지 않고, 대신
소상공인시장진흥공단 **상권정보시스템**(https://sg.sbiz.or.kr) 상권분석 보고서에 보이는
유동인구 값을 구역마다 이 파일에 적습니다.

- 적은 구역은 화면에서 실측으로 표시됩니다 (`출처: 소상공인시장진흥공단 상권정보시스템 유동인구`).
- 아직 안 적은 구역은 기존처럼 가상 수치로 남고, 실측 구역이 하나라도 있으면 목록에 `· 추정`으로 구분됩니다.
- 파일을 저장하면 **서버 재시작 없이** 다음 조회부터 반영됩니다.

## 1. 작업 순서 (구역 1개당 약 3~5분)

1. https://sg.sbiz.or.kr 접속 → **상권분석** 메뉴.
2. 아래 표의 구역 좌표를 지도 검색창에 넣거나 지도를 그 위치로 옮긴 뒤, **반경(원) 그리기**로
   표의 `radius_m`만큼 원을 그립니다. (정확히 같을 필요는 없습니다. 원의 중심을 구역 좌표에
   맞추는 것이 중요합니다.)
3. 업종은 아무거나 선택(유동인구 값은 업종과 무관) → **분석하기** → 보고서에서 **유동인구** 항목을 엽니다.
4. 보고서에서 다음 값을 읽습니다.
   - **일평균 유동인구** (명) → `daily_average`
   - **시간대별 비율** (%) → `time_bands_pct`
   - **요일별 비율** (%) → `weekday_pct`
   - 보고서 상단의 **기준 연월** → `reference_month`
5. `footfall_measured.json`에서 해당 구역 id를 찾아 값을 채웁니다. 아래 규격 참고.
6. 저장 후 검사: `cd backend && python -m app.services.footfall_measured`
   (또는 브라우저에서 http://localhost:8000/api/footfall/status → `measured` 항목)

## 3. 파일 규격

파일: `backend/app/data/footfall_measured.json` (UTF-8, JSON). 구역 하나를 채운 예:

```json
"gaeksa": {
  "name": "객사길",
  "sbiz_area": "객사길 반경 260m",
  "collected_at": "2026-09-13",
  "reference_month": "2026-07",
  "daily_average": 18450,
  "time_bands_pct": { "00-06": 3.8, "06-11": 17.9, "11-14": 20.6, "14-17": 19.7, "17-21": 26.1, "21-24": 11.9 },
  "weekday_pct": { "mon": 13.1, "tue": 13.4, "wed": 13.6, "thu": 13.9, "fri": 15.2, "sat": 16.3, "sun": 14.5 }
}
```

| 필드 | 필수 | 형식 | 설명 |
| --- | --- | --- | --- |
| `name` | – | 문자열 | 사람이 보기 위한 이름. 화면에는 `footfall_areas.json`의 이름이 쓰입니다. |
| `sbiz_area` | – | 문자열 | 보고서에서 어떤 범위를 잡았는지 메모 (나중에 검증용). |
| `collected_at` | – | `YYYY-MM-DD` | 값을 옮겨 적은 날짜. |
| `reference_month` | 권장 | `YYYY-MM` | 보고서의 기준 연월. 화면 하단 "기준월"에 표시됩니다. `2026.07` 같은 형식은 오류. |
| `daily_average` | **필수** | 양수 | 일평균 유동인구(명). 쉼표 없이 숫자만 (`18450`). |
| `time_bands_pct` | **필수** | `{"HH-HH": 비율}` | 시간대별 비율(%). 구간이 `00`시부터 `24`시까지 **빈틈·겹침 없이** 이어져야 하고 합이 100(±2)이어야 합니다. 보고서의 구간이 템플릿(00-06 / 06-11 / 11-14 / 14-17 / 17-21 / 21-24)과 다르면 키를 보고서 구간에 맞춰 바꿔도 됩니다 (예: `"09-12"`). |
| `weekday_pct` | 선택 | `{"mon"…"sun": 비율}` | 요일별 비율(%), 합 100(±2). **7개 요일을 모두 적거나, 전부 `null`로 두세요.** 비우면 평일·주말 하루 총량이 같아집니다. |
| `hourly` | 대안 | 숫자 24개 | 0시~23시 값을 직접 구한 경우에만. 있으면 `time_bands_pct`보다 우선하고, `daily_average`가 함께 있으면 합계를 거기에 맞춥니다. |

### 화면 값이 계산되는 방식

- 평일 하루 총량 = `daily_average` × (월~금 비율 평균 × 7 / 100), 주말은 토·일 평균으로 같은 식.
- 각 시간대 구간의 합은 `time_bands_pct` 비율을 정확히 따릅니다. 구간 안에서 시간별로 나누는 모양만
  구역 성격(상업지·관광지·주거지 등) 곡선을 빌립니다 — 보고서가 구간 비율까지만 주기 때문입니다.

## 4. 자주 나는 오류

검사 명령 또는 `/api/footfall/status`의 `measured.errors`에 사유가 뜨고, 그 구역은 고칠 때까지 가상 수치로 남습니다.

| 메시지 | 원인 |
| --- | --- |
| `비율 합이 100이어야 합니다 (현재 97.0)` | 구간 하나를 빠뜨렸거나 잘못 읽음 |
| `06시~11시 구간이 비었거나 겹칩니다` | 구간 키가 서로 이어지지 않음 (`"00-06"` 다음은 반드시 `"06-…"`) |
| `마지막 구간이 24시까지 와야 합니다` | 마지막 키가 `"21-24"`처럼 24로 끝나야 함 |
| `daily_average: 숫자여야 합니다` | `"18,450"`처럼 따옴표·쉼표가 들어감 |
| `weekday_pct: sat, sun 값이 비어 있습니다` | 요일을 일부만 적음 → 전부 적거나 전부 `null` |
| `reference_month: 'YYYY-MM' 형식` | `2026.07`, `202607` 등 |

값이 일부만 채워진 구역(예: 일평균만 적고 시간대 비율은 `null`)은 오류가 아니라 "아직 비어 있음"으로
취급됩니다. 즉 중간 저장해도 화면이 깨지지 않습니다.

## 5. 출처 표기

화면 하단 출처 문구는 이 파일 맨 위의 `source_label`에서 옵니다. 다른 출처(예: 지자체 보고서)를 쓰면
그 값을 바꾸고, 구역별로 출처가 다르면 `sbiz_area`에 메모해 두세요.
