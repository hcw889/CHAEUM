# 매물 공간 사진

시각화 화면(`/visualize/[id]`)이 "현재" 이미지로 쓰는 실제 촬영 사진을 두는 곳이다.

## 넣는 방법

파일 이름을 매물 id로 맞춰 그냥 넣으면 된다. 코드 변경은 필요 없다.

```
b1.jpg
b2.png
b7.webp
```

지원 확장자: `.jpg` `.jpeg` `.png` `.webp`
파일이 있으면 그 사진을 쓰고(`source: "file"`), 없으면 매물의 노후도·채광 점수와
`thumbnail_color`로 그린 참고용 공실 이미지를 대신 쓴다(`source: "placeholder"`).

프론트는 이 구분을 그대로 표시한다 — "매물 등록 사진 사용 중" / "매물 참고 이미지
사용 중 (촬영 사진 미등록)". 즉 참고용 이미지를 실제 매물 사진인 것처럼 보여주지
않는다.

## 시공 후 사진 (선택)

실제로 리뉴얼이 끝난 매물은 `{매물id}.after.{확장자}`로 시공 후 사진을 함께 넣을 수
있다. 생성 모델이 연결되지 않은 환경에서는 색보정 미리보기 대신 이 사진을 "적용 후"로
보여준다.

```
b1.png          # 시공 전 (현재)
b1.after.png    # 시공 후
```

이 경우 응답의 `mode`가 `demo`가 되고, 화면은 "실제 시공 전/후 사진 · AI 생성 결과가
아님"을 명시한다. 입력한 컨셉과 무관한 고정 이미지이므로 생성물로 오인되지 않게 하기
위함이다. `HF_TOKEN`이 설정되면 실제 생성이 우선한다.

## 권장 사양

- 가로:세로 4:3 정도, 긴 변 1024px 이상 (내부에서 768x576으로 리사이즈된다)
- 집기가 빠진 공실 내부가 잘 보이는 정면 사진일수록 생성 결과가 좋다

## git 추적 제외

이 디렉터리의 이미지 파일은 **git에 올라가지 않는다**(`.gitignore` 참고, 이 README만
예외). 출처·저작권이 확인되지 않은 사진이 저장소에 영구 기록되는 것을 막기 위함이며,
각자 로컬에 놓고 쓰는 데모 자산으로 취급한다.

그래서 clone 직후에는 이 디렉터리가 비어 있고, 모든 매물이 참고용 이미지
(`source: "placeholder"`)로 뜬다. 정상 동작이다. 사진에 의존하는 테스트는
자동으로 skip된다 (`backend/tests/test_match_reuse.py`,
`frontend/tests/visualize.spec.ts`).

나중에 권리 확인이 끝난 사진을 팀 전체가 공유해야 하면, 그때 `.gitignore`에서
해당 파일만 예외 처리(`!backend/app/data/photos/b1.png`)하면 된다.
